Owner subscription runtime feasibility

2026-09-24 · P6 bounded feasibility · LIVE subscription calls; local CLI · Root verified no-inference route and retained evidence

Decision for the build

Keep hosted execution blocked. This proves the owner’s official CLI can complete and interrupt a text-only turn. It does not complete P6, connect Remold tools, or establish a hosted tenant boundary. No new owner sign-in is needed for this narrow route. The authorized two-turn allowance is consumed; this runner refuses an accidental repeat.

Observed and recorded

  • Unmodified codex-cli 0.156.1 completed the stdio handshake using existing ChatGPT-managed sign-in. The reported plan was prolite. Credentials were neither read nor copied.
  • Configured model gpt-6-luna, reasoning high, service tier default stayed unchanged. The first turn returned exactly RUNTIME_OK.
  • The second turn entered reasoning, then ended interrupted four milliseconds after the interruption request. No output text had arrived, so active text-stream cancellation is unproven.
  • No tool items or server-initiated tool requests appeared. The server confirmed an ephemeral thread, read-only sandbox, network access disabled for model tools, and approval policy never. The process exited after 7,809 milliseconds.

Usage and exact limits

The CLI reported 8,023 input tokens and 7 output tokens for the completed turn, 8,030 total, no cached input or reasoning-output tokens reported. These are runtime telemetry, not an invoice. The interruption emitted the same cumulative and last-turn counters; no incremental interruption usage was established. Interrupted usage and subscription marginal dollar cost remain unknown.

The runner allows one concurrent turn, two turn starts in total, a 60-second completion wait, interruption after first text or five seconds, a ten-second interrupted-terminal wait, and a 100-second process watchdog. It kills its child process on exit. These are local execution controls, not a provider-enforced token, dollar, or internal-model-call ceiling. A turn can contain multiple model calls. The two prompts requested only synthetic text. There were no customer records, messages, deployments, or paid API keys.

Contract gap: per-continuation authorization

The generated installed server-request schema exposes tool approvals, dynamic tool requests, account-token refresh and attestation, but no synchronous pre-model-call permit request. The documented hooks cover tool, prompt, compaction, session and interruption events; those do not establish a gate before every internal inference. A client can control turn starts and request cancellation; neither observation establishes hosted C3. This is a documented-surface finding, not proof that no future runtime version could provide the missing mechanism.

Budget surfaces, still unverified

The installed schema includes thread/goal/set.tokenBudget, goal statuses budgetLimited and usageLimited, and the sessionBudgetExceeded error variant. These are schema-present, enforcement semantics unverified, not a C3 permit gate. The official app-server page documents setting and tracking a goal budget. The official Goals guide describes continuation decisions at idle turn boundaries and stopping substantive work on budget exhaustion. Neither fetched page establishes a provider-enforced ceiling or bounds overrun within an active model call. The app-server page does not explain sessionBudgetExceeded. No new goal, budget experiment or inference was run.

What remains blocked

  • Hosted adoption, per-model-call and continuation permits, an enforceable residual-usage bound, and cancellation of an actively emitting stream.
  • Actual scoped Remold MCP integration with allowed and refused tool calls. This task deliberately did not retry the separately blocked I1 authorization audit.
  • Cross-tenant filesystem/environment/network isolation, budgets across concurrent jobs, kill-switch propagation, restart recovery, late results and delegated descendants on this runtime.
  • Customer-owned supported authentication and hosting terms. This owner-local CLI naturally retains access to the owner’s existing CLI auth store; it is not a customer execution sandbox. No home directory or subscription credential was copied into a hosted environment.
  • Remaining behavioral independent verification, review of a concrete runtime-selection decision, and D0A approval.
