How it works now

The executor runs the sandbox and meters every streamed token itself. It then sends one settle call with these fields:

  • meter: the executor's own token count.
  • reported: the usage the guest reported.
  • killed: true if the run was killed, or if the global flag is off at send time.
  • output: only if the run was not killed and the output is at most 64 KB.

Inside one transaction, settle does four things in order:

  1. Reads H0 adapterStatus, which covers cancel, org kill, revocation and lease.
  2. Calls H0 reconcile to bill the usage.
  3. Flags an under-report if the guest reported less than the meter.
  4. Inserts the output as a records row only if nothing stopped it.

settle.ts is proof-owned. contract.ts, harness.ts and schema.ts are still byte-identical to proofs/contract/convex (evidence/sha256.txt), and run.mjs refuses to run otherwise. disable() returns only after any apply already sent has settled, so after it resolves nothing applies.

Needs an H0 amendment (recorded, not fixed)

  • Non-renewable 2 s lease. Any hosted run longer than about 2 s after claim is cancelled. Real agent turns need a fenced lease renewal.
  • The global kill is per host. It is a flag in the executor process. A kill across several hosts needs a control-plane field. H0 has only the per-org readonly.
  • The org kill is not "late" in H0 reconcile. P6 no longer depends on this, because of the atomic settle. The verifier found the same shape in I1 at convex/integrations/outcomes.ts:36, where it is an audit misclassification rather than a write bypass.
  • Spend can overshoot before the kill lands. A model that ignores its limit billed 9 units against a reservation of 4. H0 then flags an overrun and holds the tenant. Real providers need their own token limit enforced; the executor kill alone is not a hard cap.
  • Usage trust. The meter is now the floor, but it counts the stub's stdout lines. A real executor must meter at the trusted model runtime, not inside the tenant process.

What stays open in P6

  • A real hosted executor. This is a local proof harness on colima-remold-proof.
  • OS-level isolation on the real host. Docker on a shared kernel here, with no gVisor or Firecracker and no escape testing.
  • A real-model smoke test with provider-origin usage, active stream cancellation, and step or tool limits.
  • The subscription route, which is still owner-local only in proofs/runtime/report.html.
  • The funding gate: default zero, and it needs a live funding method, provider terms and a numeric cap.
