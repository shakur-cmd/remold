Counterexample

The real fixture had no symlinks, and every file was 33:33 with mode 755 or 644, so it could not show whether the copy keeps unusual metadata. I ran the builder's exact manifestCode and cp -a, with the same four added capabilities, in a throwaway tmpfs container with no volumes. The copy kept two symlinks (one dangling), a setgid 2750 directory, a setuid 4755 file and mixed owners. The manifest caught all seven mutations: chmod, chown, lchown, symlink retarget, byte change, extra file and root mode.

  • Builder probe …media-probe-after-3c238bbc (exit 0) is not referenced in the root evidence.
  • Probes leave anonymous volumes behind. private/tenants/media-replacement.env (0600, gitignored) still holds B secrets.
  • Legacy B shares config-b, media-b and logs-b with the replacement, so never run both. Rollback is untested.
  • The resume guards for the prepared, fenced and copied phases were reviewed in source only. On the final source, only the verified no-op path ran. The fenced-phase guards look sound: they refuse copying while a replacement exists, refuse a non-empty partial destination, and re-verify both sides before creating the replacement.
