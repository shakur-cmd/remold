Test-strength gaps (code correct, but no committed check would catch a regression)

  • No committed importer tests. run.mjs only sends well-formed pages, so these guards go untested: PAGE_GAP, foreign-tenant CAPTURE_SCOPE, REPLAY_CHANGED, TRAVERSAL_IN_PROGRESS and MISSING_CONTACT_MUST_SUPPRESS. I confirmed they work only in my isolated harness (baseline.json). Removing each guard makes its case fail (importer-mutants/m-*.json).
  • The "origin cannot change tenant" check cannot fail. Both receiver.test.mjs and callback-replay.mjs send the foreign X-Origin-Base-URL only with a body that is already stored, so INSERT OR IGNORE hides any rebinding. A mutant that stores the tenant from that header still passes the suite. The real receiver stores a fresh body with a foreign origin as tenant a (receiver-probe.json).
  • The JSON-object refusal (array → 400) and the fatal UTF-8 refusal (→ 400) work at runtime, but removing them passes the suite. The duplicate-signature-header guard is an equivalent mutant: Node joins the two headers and the signature regex already refuses them (raw socket gives 401, see receiver-duplicate-header-raw.json). The 400 for that case in receiver-probe.json comes from how my client built the request, not from the receiver.

Risks beyond the claims

  • Concurrent-ID skip (analysis only, not reproduced; no extra native writes allowed). The cursor is the highest native submission ID. If two submissions insert at the same time and the lower ID commits after the higher one is already visible, that lower ID is skipped forever. Tested runs were sequential, so this is not covered. It must be solved before any production claim.
  • The 100-capture cap wedges the instance. Reproduced in the isolated copy. After 100 captures, the 101st finish fails with CAPTURE_BOUND. The finished pending traversal stays, and every new scan then gets TRAVERSAL_IN_PROGRESS. This is the acknowledged max100, but the consequence is a permanent stall with no operator recovery path.
  • Observations are not ordered. A later-committed stale "unsuppressed" observation overwrites a recorded suppression (reproduced). This falls inside the acknowledged read/finalize race boundary. With the prescribed driver, observations are read right before finish, so in practice this is a delay.
  • Convex refuses non-ASCII result keys. This fails closed, so only liveness is affected. Native field aliases are ASCII.

Acknowledged open, not claimed by this slice

Read/finalize observation race; max100; no installed scheduler or callback consumer (the proof driver polls); provider-history rollback; native existing-email identity overwrite; no CRM applyChange integration; native deletion and queue redelivery (webhook_queue stayed 0 and the 3 outage callbacks were logged, not retried); production auth; rate limits, browser/DNS/TLS, dynamic publishing, backup restore, LIVE delivery. I1 was excluded and not retried. This verdict does not certify P2 or any dependency.
