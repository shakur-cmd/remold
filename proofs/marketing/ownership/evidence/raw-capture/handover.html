Done and proven (by the builder only)

  • Before (IV D1, rerun unchanged): an admin mapped email and firstname and added a remove-DNC action on the live admitted form A34. Four posts through the running edge replaced the owner's first name (owner 245), dropped DNC from 1 to 0, created new contact 246, and linked all 4 submissions. Evidence: d1/a4-post-publish-edit-a.json.
  • After: the edge makes zero Mautic form posts. Each submission goes to one tenant-bound, validated, idempotent Convex mutation, and the edge answers 200 only after the mutation has committed. The same D1 edit was live on the old native forms A34 and B29 during the run. Mautic form submissions stayed exactly at A 184 and B 92 for the whole run, and the owner's profile and DNC did not change.
  • 16 concurrent posts per tenant, with both tenants at once: 16 of 16 acknowledged and stored on each tenant, with no loss and no deadlock.
  • Lost reply after commit, then client retry: the first reply was dropped after the commit and the client got 502. The retry got 200. Exactly one capture was stored. Reusing the same nonce with changed values was refused with 409.
  • Reconcile once: the reconciler was crashed right after creating a contact and before recording it. On restart, the new email's contact was found and recorded as existing, with no second create. On each tenant exactly one contact was added (A 253 to 254, B 70 to 71), and all 17 captures were settled once. The existing owner was never overwritten. DNC, campaign, queue and mail counters did not change. A third run found nothing to do.
  • Tenant isolation: each tenant's inventory held only its own captures. B stayed untouched while A reconciled. A's reconciler key could not settle a B capture, and an edge key could not read.
  • Mutants (each made the SERVICE proof fail):
    • Idempotency lookup removed: 7 checks failed, including duplicate captures on retry and no conflict detection.
    • Tenant binding removed from the reconciler read: reconciler A wrote 3 contacts into A's Mautic from other captures before settle refused, and 6 checks failed.
    • Reconciler allowed to overwrite existing contacts: both owners' first names were replaced, and 2 checks failed.
  • This closes a P2 gap (the public write path). It does not complete P2 or D0M.

How it works now

PieceWhat it does
publishing/server.mjs (edge)Serves an edge-owned form at /form/intake with a signed token and a fresh random nonce per render. On POST it validates as before, then calls capture:capture on the raw-capture Convex backend with its own tenant edge key. It returns 200 only on a committed success, 409 when the nonce was already used with other values, and 502 otherwise. It no longer posts anything to Mautic. It still proxies the published page and asset with GET only.
rawcapture/convex/Its own Convex project on its own backend container. Keys are stored only as SHA-256. The tenant always comes from the key, never from the caller. capture is idempotent per tenant and nonce, and refuses a nonce reused with different values. The reconciler key can only read pending captures for its own tenant and settle them. Captured values are suggestions only.
rawcapture/reconcile.mjsRuns once per tenant through the Mautic contacts API. It creates a contact only if no contact has that email. An existing email is only linked and never edited. More than one match is marked ambiguous and nothing is written. It never reads or writes DNC. A crash between create and settle heals on the next run, because the contact is then found by email.
rawcapture/setup.mjsCreates the backend container remold-marketing-proof-capture. It uses the same pinned Convex image and is attached to both internal tenant networks with ip_forward=0, which is checked. It has no Docker port binding. The host reaches it only through a separate loopback SSH forward on 127.0.0.1:3547. Setup also deploys the functions and registers four keys: edge and reconciler for each tenant.
rawcapture/replay.mjsThe one-shot SERVICE proof: 43 checks, with evidence written even on failure.

Incidents and limits (please read)

  • I raised a memory limit, on my own new container only. The capture backend was created with 256 MiB and was OOM-killed during run r2, in the 32 concurrent mutations, after surviving r1 and three mutant runs. I raised it to 512 MiB with docker update, and setup.mjs now creates it at 512 MiB. It sat at 115 MiB after r3. No existing container's limit changed. After the restart, 4 of r2's tenant B captures were still pending and were reconciled by the drain run, but r2's client statuses were lost, so I claim nothing about r2. db-b read 480 of 512 MiB after r3 and did not restart. The reconciler adds only a few API calls per capture.
  • The capture container first came up with ip_forward=1. The setup check caught this, and I recreated the empty container with --sysctl net.ipv4.ip_forward=0 before any data went in.
  • The lost-reply case is simulated with a proxy that drops the reply after the commit, inside a second edge instance in the tenant's edge container. That instance uses the deployed source and config. The deployed edge process itself was not killed.
  • The nonce is unsigned. A client can choose its own nonce, and that only dedupes that client's own posts. It is 128-bit random, so it cannot be guessed across users.
  • The reconciler assumes one instance per tenant, with no lease. If an admin creates the same email in Mautic between the reconciler's lookup and its create, Mautic's API would update that contact. The "ambiguous" branch (more than one match) is implemented but not exercised, because Mautic merges on email and I could not create a duplicate cheaply.
  • The mutant runs left synthetic leftovers: duplicate capture rows for the idempotency mutant's nonces, 3 cross-tenant contacts in A from the tenant mutant, and first names overwritten on the overwrite mutant's owners, which are synthetic. The native forms A34 and B29 were reverted to unmapped with no actions after every run.
  • d1/a4-post-publish-edit.mjs imports the deleted admission module. To rerun the "before", check out 0c2cdf5. The "after" D1 check is in rawcapture/replay.mjs.
  • Still open for P2 and D0M: core Person reconciliation in Remold Convex and applyChange attribution, send-time suppression, a scheduled reconciler, and a production auth design for edge keys. This proof's keys are per-tenant bearer secrets in a local file.
