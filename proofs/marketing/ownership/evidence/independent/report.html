Policy assessment against the approved core

C1 says Convex owns customer records, and engines own execution and observed outcomes. Suppression must take precedence, and re-import cannot erase it. With raw capture, the engine does no identity matching at all. Resolution, duplicate handling and attributed CRM writes move entirely into Remold. That fits C1 better than any mapped-field path, because every native merge path proven here can delete DNC. This assessment does not claim that Convex core writes, send-time suppression or applyChange attribution are built for this path. They are not.

This supersedes one consultation assumption for the raw intake path only. The consultation's N6 gate required "at least one mapped field". It exists so the submission never attaches to the tracker contact. With the fixed upstream Blocked-Tracking=1 cookie, the tracker returns null, so no mapped field is needed. The native API already accepts null mappings, and no framework patch was used. If the mapped-email kiosk path is used instead, all of the consultation's gates still apply unchanged: N2 duplicate-email ambiguity (never take the first match), N3 concurrent new-email duplicates, N4 alias checking, N5 send-time consent and N6 at least one mapped field.
