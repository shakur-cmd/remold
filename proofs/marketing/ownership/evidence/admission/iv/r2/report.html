2026-09-26 · scope: proofs/marketing at 422e818 (p2/admission-2026-09-26) · level: SERVICE, isolated local containers in colima-remold-proof, synthetic data · checker: independent verifier session (Claude Opus 5.5), not the builder · supersedes the round-1 verdict on D1 (../report.html) · verdict: D1 CLOSED on the public path; reconciler has one new real defect

Your calls

  • One bad email stops reconciliation for the whole tenant. The edge and Convex accept emails that Mautic will not take, such as iv%pct-…@example.invalid (Mautic answers 400 on create) or %@%.% (Mautic search matches all 216 contacts, so the size guard throws). The reconciler throws, exits 1, and on every later run stops at the same oldest pending capture. Nothing behind it ever reaches Mautic. Any public visitor can do this with one post, and so can a real typo. Fix: settle a capture that Mautic refuses as a new outcome (for example rejected) and carry on, instead of throwing. Needs a builder change and a test.
  • No lease on the reconciler causes real duplicates, not only the race the builder disclosed. I ran two reconcilers at once on 12 captures for 6 emails. Mautic created two contacts for one email (282 and 283), one reconciler crashed on a settle conflict, and every later capture for that email will be settled as "ambiguous" forever. Choose: a single-writer lease in Convex (claim a batch before calling Mautic), or run it strictly as one scheduled job and accept the risk.
  • The admin race overwrites names, not DNC. The reconciler looks the email up and then creates the contact. If an admin creates the same email between those two steps, the "create" updates the admin's contact: its first name became the public suggestion and the capture was recorded as created. DNC was kept. This is the disclosed gap, now with measured harm. It only matters if you accept D0M with a reconciler that creates through Mautic's upserting API.

Keys and the loopback forward

  • Raw edge and reconciler keys are found only in private/rawcapture/keys.json, host private/publishing/config-{a,b}.json, and each edge's own /public-config.json. Edge A holds only A's keys and edge B only B's. No raw key is in any docker inspect, any container log, the capture volume, or any git-tracked file. The instance secret is in the capture container's env and /convex/data/credentials, as Convex requires. Admin key and instance secret are in private/rawcapture/state.json (b4-keys.json, which lists locations only).
  • My own scan once echoed secrets into an uncommitted error field. I deleted that file, moved secrets to stdin, and checked all 40 committed evidence files contain none of the 8 secrets. I also deleted my round-1 copies in private/iv-admission/.
  • 3547 listens on 127.0.0.1 only. The LAN address 10.0.0.192 and ::1 are closed. Without keys: admin endpoints return 403 BadDeployKey. Public functions and _system queries return an error status. Internal registerKey is refused. A text/plain request of the kind a browser page could send is rejected with 400 (b5-loopback.json). The remaining exposure is any local process that holds a key file.
