Newly found gaps (not scoped away)

  • Anonymous contacts from public reads. Every page GET/HEAD and asset download through the edge makes native Mautic create a new unidentified contact plus a page_hits/asset_downloads row. This replay added 4 per tenant (A 156–159, B 17–20), and every root run did the same. The edge strips client cookies, so each view is a fresh contact. This is unbounded native writes from anonymous traffic. The root report's line "native tracking is not supported by this slice" does not disclose that server-side tracking still fires. It is not a tenant crossing and not a false ACK. Evidence: logs/anonymous-contacts.txt.
  • Unit tests miss three protections. These mutants still pass all 5 tests: UTF-8 fatal removed (the tests use only %ff, never raw bytes), success!==1 removed (the tests always pair success:0 with errorMessage) and in-stream request cap removed (the tests never send chunked bodies). The installed code has all three, and runtime cases confirmed UTF-8 and the chunked cap. The success-flag guard has no failing check anywhere.
  • No rate or abuse limits on form POSTs or page/asset reads. The static per-form token is replayable. The root report already states that the token is not anti-abuse.
