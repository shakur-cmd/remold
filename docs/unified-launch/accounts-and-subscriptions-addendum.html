P6 acceptance changes

  • Keep existing authority, task isolation, cancellation, late-result, restart and tenant-boundary checks. An official CLI process must use the intended subscription route without falling back to a paid API key.
  • Apply bounded runtime, concurrency and model-call allowances. When subscription quota is unavailable, pause and report it; do not buy credits or enable overage. Exact runtime limits must be captured with the proof.
  • The first user-owned CLI worker is a connected/external agent proof only. Check its execution permit immediately before process launch, and enforce current Remold authority for every tool call. A process can make several model calls: launch fencing alone does not satisfy hosted C3. Hosted mode remains blocked until the unmodified runtime can demonstrate a permit before every new model call and continuation, active-stream cancellation, and the documented in-flight tail. If a runtime cannot provide that enforcement, reject it for hosted mode or explicitly lower its mode through P6 and D0A; do not silently weaken the contract.
  • Record model, duration, outcome and reported usage. Subscription marginal dollar cost is unknown unless an authoritative source provides it. Never label unknown cost as $0 or convert runtime token telemetry into a claimed invoice.
  • Demonstrate actual subscribed CLI execution plus allowed and refused Remold tool calls. A stub, login status or successful text-only response alone does not prove the integration.
  • Preserve the original hosted/external scope and D0A selection dependencies. If managed subscription hosting cannot satisfy official provider terms and isolation, record the constraint and ask Opus before escalating a concrete choice to the owner.
