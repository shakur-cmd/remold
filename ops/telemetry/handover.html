Implemented and checked

REST responses schedule a canonical server-span aggregate after the response is built. Internal queries expose counts, exact bounded status labels, server/client errors and fixed latency histograms. Probe receipts distinguish observed coverage, a grace period and missing transport/collector evidence. No customer fields, tenant IDs, keys, request URLs, query strings, response bodies or error text are stored.

Three behavior tests failed before implementation; the expanded five-test suite passes. Repository tests and typecheck pass. The final disposable-backend service replay passed. The injected failure measured 303 ms and HTTP 500; after removing it the handler measured 0 ms at millisecond clock resolution and returned HTTP 200. All 50 simultaneous requests produced aggregate receipts. A real scheduler rejection preserved the domain response. Public metric calls were refused, expired rows were removed, and the real three-minute transport gap was observed and recovered. Source and results still require independent review before this slice is certified.

Definition and limits

ItemDefinition
SourceOne server span from HTTP-action entry through constructing the domain response. Auth failures and caught errors are included. Scheduler overhead, platform queuing, network latency, browser paint and requests that crash before response construction are excluded.
Scope and statusOne fixed REST-wide label plus a separate probe label. Exact statuses 200, 201, 400, 401, 403, 404, 409, 429, 500; any other code is labelled other. Error-class counters still count an unlisted 4xx or 5xx. Server error rate is observed 5xx divided by observed REST requests. Probe spans are excluded from business request totals.
Latencyrest-handler-ms-v1 buckets: ≤10, 25, 50, 100, 250, 500, 1000, 2500, 5000 and 10000 ms, followed by overflow. Median/p95 are upper bounds, never interpolated values. With nonzero samples, a null percentile means above 10000 ms; with no samples it means no data.
WindowExplicit epoch-minute start/end, at most 60 minutes, including a marked partial current minute. Operator supplies asOfMinute, so polling changes query arguments and does not rely on time automatically invalidating a cached query.
Sample and denominatorAll delivered spans, no first-N sampling. Observed counts are not asserted to equal all actual traffic. A canary proves one successful path each minute; partial loss remains unknown. A zero denominator returns null rates and latency.
CoverageCovered: a successful probe receipt and corresponding 200 probe metric. Provisional: an uncovered minute less than three minutes old. Transport gap: successful probe receipt, no matching metric after grace. Collector gap: no successful probe receipt after grace. Unconfigured/failed probes are exposed. Zero observations with missing coverage is unknown traffic, not healthy zero traffic.
ReleaseCommitted convex/release.ts is unknown. Only a 40-character lowercase hexadecimal tag is retained; malformed tags become unknown. Four distinct releases per minute are retained; later distinct tags use overflow, preserving totals. No request-controlled version input exists. Mutable backend env SHA was deliberately avoided.
Cardinality and retentionTwo route labels × ten status labels × at most five release labels = 100 aggregate rows/minute. Readers are bounded to 6001 rows and 61 probe receipts. Raw spans are not stored. Records older than 65 minutes are purged every five minutes, 500 rows per transaction with bounded follow-up batches. Each ingestion also deletes one expired row, preventing indefinite accumulation from a stalled purge alone. Purge lag is exposed. Opportunistic expiry means retained data volume remains bounded under ordinary internal writers; total function invocations still scale with requests.
Cost and recovery gapNo paid ingestion provider. Each request attempts one scheduler write and later one aggregate mutation; the probe adds a periodic local action/receipt. Unauthenticated floods still incur function work. Production overhead, quota/cost bounds and platform-count reconciliation remain unverified. Histograms are the retained measurement source; individual discarded spans cannot be reconstructed from this table.

Measured overhead and proof limits

The local alternating-block client measurements contain 20 requests with delivery enabled and 20 disabled. Mean client time was 5.549 ms enabled and 3.497 ms disabled. The raw samples are retained in service.json. These are noisy synthetic local observations, not a production guarantee or a causal improvement claim. The 303 ms to 0 ms handler comparison is intentional fault removal, not an advertised product speed result.

Operator path and configuration

telemetry:report is an internalQuery, callable through an authorized Convex operator CLI, not a customer API. Arguments: {"minutes":60,"asOfMinute":<current UTC epoch minute>}. REMOLD_METRICS_PROBE_SECRET must be a random string of at least 32 characters. The cron uses the deployment’s CONVEX_SITE_URL. REMOLD_METRICS_OFF=1 disables span delivery while preserving domain responses and probe receipts, producing an explicit gap. Without probe configuration, coverage remains unconfigured/unknown.

The only currently defined platform operator authority is the existing internal-admin path. There is no platform UI role or public metric endpoint. Customer and browser events cannot write canonical counters. Tenant-level drill-down and masked business metrics remain for their domain jobs and I10.
