Production safety boundary

  1. An authenticated provider adapter supplies safetyTargets: tenant binding, immutable document/provider identity, currency, paid/refunded amounts, recurring status and provider version. It does not create charges or consent.
  2. Human owner/admin calls safety.prepare for an exact positive refund or zero-amount client recurring cancellation. The approval binds payload, membership row ID and epoch, and expires after 60 seconds.
  3. The same signed-in human calls public safety.consume. Convex verifies the JWT at the call. The transaction rechecks exact membership/epoch, record masks, binding, connected account, target identity, adapter availability and paid-minus-refunded-minus-pending headroom. It reserves once, marks consumed and schedules a trusted action.
  4. There is no production adapter implementation yet. The code-owned registry is empty, so consume fails before reservation. The SERVICE proof replaces only that registry in the isolated scratch copy with an explicitly SIM adapter that yields an unknown outcome.
  5. The scheduled action uses opId:step:1 idempotency and opaque vault references. Failure remains outcomeUnknown and retains money headroom. Ordinary operation dispatch refuses safety commands.
  6. Authenticated receipts settle truth once even after removal/cancellation. Financial unknowns cannot be cleared by an owner guess. Final absence requires an operator-registered provider-and-capability rule with semantics and proof reference, followed by an authenticated adapter lookup result. Unexpected late acceptance after final release retains truth and creates a payment anomaly hold.

Session guarantee

Membership removal, replacement and epoch changes are checked transactionally. External sign-in session revocation is bounded by the access token lifetime; this implementation does not claim WorkOS introspection or immediate upstream session revocation. Synthetic signed JWTs and expiry are proven locally. Measuring the real AuthKit access-token lifetime remains a separate identity evidence item.

Read and delegation ceiling

Unrestricted old agents retain their authorized legacy object behavior using immutable object IDs. New scoped agents start without implicit reads. Fields and records are projected on production reads, writes use applyChange, and changing masks invalidates dependent approvals. Restricted humans cannot mint legacy broad-read keys or replace legacy wildcard grants; their recovery path is createScoped plus grants within their effective record/field ceiling. Independent human grants survive revocation of a separate delegation chain.
