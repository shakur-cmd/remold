Detail

Method. Canonical owned driver agent-setup/lib/cdp.py, called by subprocess (not copied), on profile ~/.web-automate/chrome-profile. Every navigation, eval, click and box call carried --target, account label “Shakur Remold staging preview”, and that run's four allowed origins (preview, api.workos.com, detailed-neutron-08-staging.authkit.app, accounts.google.com). No unknown origin came up. Every action was checked with a separate DOM probe or target URL read afterward. CDP acknowledgements were not counted as proof. Reloads were proven real with a window marker that disappeared, plus navigation type reload. Record deep links came from the Companies row link in the UI, not a guessed route.

Nuance. The first sign-in on each preview reused an existing staging AuthKit session, so Google never prompted. The deep-link check came after a real logout, so it went through the full AuthKit login page, then Google's account chooser. There I picked only the entry matching the account the app session had just used.

Privacy. I did not read cookie, token or storage values, network auth data, page bodies or account PII. Probes return booleans and control labels, and drop any string containing “@”. URLs are recorded as origin + path only. Raw probe JSON is kept in a private temp dir (mode 0700), not in the repo.
