Paperclip independent P1 security check

2026-09-24 · Reviewer: /root/c0_verifier · SERVICE · Early P1 only

Review decision

Reject the tested default co-resident process executor and ordinary agent-key topology for Remold multi-tenant execution. Root and Opus concur. This is a candidate recommendation, not a completed P1 or D0A selection. No owner decision is needed for this bounded rejection.

Done and proven independently

  • A fresh actual Paperclip heartbeat read the complete changed synthetic B sentinel and inherited the disposable server auth secret. The runner emitted only secret-presence booleans.
  • A normal engineer agent key read another agent’s assigned issue and exact synthetic description within company A. It could also list A’s other agent and issue.
  • A task-bridge key passed the bounded record-scope check: it read its own assigned issue, excluded A2 from its agent list, and denied A2 and B issue reads. This prevents a blanket claim that Paperclip cannot scope credentials.
  • The same A credential was denied company B’s agent list with HTTP 403. Container host-home absence was observed.
  • All three probe commands exited 0, meaning the probes completed. Default runtime and ordinary-key acceptance are false; the task-bridge scope acceptance is true. Source files and root probe were not changed.

The B sentinel is verifier-created synthetic data in the common container filesystem. It proves the lack of process filesystem separation. It does not establish that Paperclip stores actual B application records at that path. The issue was assigned to A2 and intended only for A2 in this test; no Paperclip private-issue flag or guarantee was asserted. Assignment alone did not enforce Remold’s record boundary.

Why source matches the result

Exact source and service commit: e006c18f2036d95d47ca8f7eb068670f3c54942d. Base image digest: sha256:52510c246809a1c0978e67e39a855bff6c9cfdfe2114f115791ab0add15d1411. Root’s prepared image adds embedded Postgres runtime preparation; this report reviewed the source pin and service-reported commit, not binary reproducibility.

  • Process adapter invokes the shared child runner without a local process sandbox.
  • Environment sanitizer removes PAPERCLIP variables except its explicit exceptions; it retains other server variables. The child runner merges that environment and spawns the child. Read-only root does not provide per-tenant read isolation.
  • Issue routes contain special task-bridge restrictions, and agent routes contain scoped credential handling. The first scope probe used ordinary agent API keys. A subsequent real task_bridge credential passed the bounded read checks, with a successful own-issue read as a positive control. skill_test credentials and the full task-bridge mutation surface remain untested. Ordinary keys cannot be equated with every credential type.

Credential qualification

The failed H3 ordinary-key result does not justify rejecting every Paperclip API topology. A narrower credential is operational at this pin. The default co-resident process executor remains rejected because key scope does not remove inherited server environment or separate the filesystem. Whether a separate executor using narrow credentials provides enough benefit for Remold requires the remaining candidate comparison; this report makes no selection.

Exact advisory is a separate question

The primary GHSA-gqqj-85qm-8qhf advisory, published April 16, 2026, reports a codex_local runtime using inherited ChatGPT/OpenAI Gmail access to read and send mail. It names version 2026.403.0 and lists no patched version. This independent probe used the process adapter with no host login, Gmail connector, provider credential or model call. It therefore did not reproduce the exact advisory at the pinned commit.

At the pin, agent creation leaves Codex credentials shared by default unless its API-key isolation condition applies. The default bypass flag remains true, and argument construction uses it with explicit overrides. These are source concerns, not proof that the current pin can invoke inherited Gmail. No claim of session forgery, database theft, external sending or account takeover follows from the secret-presence result.
