1. **[P1] Owner-backed trials reveal unreadable records — [convex/agentApi.ts:164](/home/old-mac-pro/work/jobs/K-blueprints/convex/agentApi.ts:164).** `requireUnrestricted` checks object and field visibility but does not require access to every record. An admin agent with selected-record grants covering all fields can therefore pass, then resolve starter-record lookups as the owner. I reproduced a records-only blueprint returning `BLUEPRINT_TRIAL` for an unreadable company’s name and `VALIDATION` for an absent name. Rollback prevents writes but does not prevent this information leak. **Fix:** require full record scope on every object before permitting owner-backed validation, and resolve existing-record references under the agent’s actual read permissions.

2. **[P1] No deployable compatible rollback target accompanies the schema expansion — [convex/lib/metadata.ts:37](/home/old-mac-pro/work/jobs/K-blueprints/convex/lib/metadata.ts:37).** Once a blueprint proposal is persisted, the previous schema rejects it. The supplied `rollback.log` explicitly demonstrates failure when deploying `050abad`; success requires manually combining old code with new validators. The release metadata and production rollback instructions do not identify that combination as a committed rollback target. **Fix:** create and pin a compatibility release retaining the expanded validator and safely handling blueprint rows, then verify rollback through the supported production deployment path.

3. **[P2] Two title changes cannot execute in one blueprint — [convex/lib/blueprint.ts:88](/home/old-mac-pro/work/jobs/K-blueprints/convex/lib/blueprint.ts:88).** Each `setTitleField` calls `retitlePage`, which invokes `.paginate()`. A blueprint setting Company’s title to Domain and Person’s title to Email fails on the second pagination—even with no records. I reproduced this with transaction limits enabled. It also breaks exports from workspaces with multiple changed titles. Convex restricts built-in pagination to one call per function execution. [Pagination reference](https://github.com/get-convex/convex-helpers/blob/main/packages/convex-helpers/README.md). **Fix:** use bounded non-pagination reads for initial retitling, or schedule retitling transactionally while keeping metadata changes atomic.

4. **[P2] Export silently loses edits to standard options — [convex/lib/blueprint.ts:210](/home/old-mac-pro/work/jobs/K-blueprints/convex/lib/blueprint.ts:210).** Export compares existing standard options only by ID. Renaming or recoloring an existing Opportunity stage through `fields.update` produces no corresponding change; I reproduced a renamed stage exporting `changes: []`. Import restores the original label/color. **Fix:** encode changes to existing option attributes with appropriate authorization, or explicitly reject an export that the current blueprint format cannot faithfully represent.

5. **[P2] Export drops retired custom fields and their reserved capacity — [convex/lib/blueprint.ts:196](/home/old-mac-pro/work/jobs/K-blueprints/convex/lib/blueprint.ts:196).** Custom fields are exported only when live; retirement instructions cover only built-in fields and custom objects’ automatic `name` field. Creating and retiring `company.legacy` exports nothing, which I reproduced. The destination loses the field definition, restoration capability, reserved key, and occupied index slot. **Fix:** export retired custom definitions, recreate them with their indexing characteristics, and retire them after creation.

6. **[P2] Export emits blueprints rejected by its own size limits — [convex/lib/blueprint.ts:227](/home/old-mac-pro/work/jobs/K-blueprints/convex/lib/blueprint.ts:227).** Export has no matching limits or final validation. A workspace with 21 custom objects exports successfully, but applying that export to a fresh workspace fails with “A blueprint can add at most 20 objects”; I reproduced this. More than 100 generated changes causes the same mismatch. **Fix:** reconcile export/import capacity while preserving atomicity, and reject unsupported exports explicitly rather than returning unusable blueprints.
