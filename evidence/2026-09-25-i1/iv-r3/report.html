  • Timing and the 1000-row scan cap. The revision-2 search fix introduced a timing signal and a 1000-row cliff (below). Both are small and go away with the same fix as the first item. Accept as low residuals, or fold them into that fix.

Repro for P (real local backend)

One workspace. The member's scope is opportunity records [Mine Deal] (amount 100) and every other object in full. The scoped agent has a read grant on the same record. The owner then creates 3 opportunities with amount 777777 and 4 ordinary ones. None of them is readable to the member or the agent.

member: records.list {objectId: opportunity, filter: {amount: 777777}, numItems: 1}, following continueCursor
  hidden value : [{n:0,done:false},{n:0,done:false},{n:0,done:false},{n:0,done:true}]   -> 3 hidden deals at 777777
  missing value: [{n:0,done:true}]                                                    (888888)
agent: GET /api/v1/records?object=opportunity&filter=amount&value=777777&limit=1
  hidden value : 200 {records: [], cursor: "<present>"}, 3 follow-up pages
  missing value: 200 {records: [], cursor: null}
member: records.list recent-first, numItems 5   before [{1,done}]  after 7 hidden [{0,not done},{1,done}]
member: records.related Acme / opportunity.company   before [{1,done}]  after [{1,not done},{0,done}]
member: events.forOrg first page of 5   before 2 events   after 0 events, isDone false
member: csv.exportPage (200 raw rows a page)   before [{1 row, done}]   after 999 hidden: [{1,not done},{0,not done} x4,{0,done}]

The cursor itself is opaque: 384 characters, containing none of the hidden ID, amount or title, in raw, base64 or base64url form (R3-P7 PASS). The leak is page length and isDone/cursor. The same mechanism works for a select filter such as stage = won. Sorting by a visible field would also place hidden rows between readable neighbours; I did not run that separately.

Suggested fix, the builder's own: when a caller's scope for the object is an explicit record list, answer from that list (fetch by ID, then filter and sort in memory, bounded by the list size) instead of paging the object index. Callers with records: 'all' never meet hidden rows in a per-object index, so their path is unchanged. For events.forOrg, and for text search without an object, restrict to readable objects and records first. This also removes F1 and F2 for record-scoped callers. Unreadable objects in cross-object text search would still need a per-object query.
