1. **HIGH. The propose path never checks an op against the grant's scope.** The scope comment defines the meaning of `'new'` and ids, but the Proposing bullet lists only readability, op count and open count. A builder following the bullets would let an ids-scope agent propose `object.create`, or field ops on an object outside its list, and no H0 case catches it. Fix: add to Proposing: "Propose names one live `setup.propose` grant. `object.create` and `ref` ops need `'new'`. Every other op's object, resolved by id, must be in the grant's ids list, or the grant must be `'new'` only if the object was created by an earlier op in this proposal. Out-of-scope but readable refuses FORBIDDEN after the read check, so unreadable still looks missing. `maxOps` and `maxOpen` are that grant's; open means pending proposals with that `grantId`." Add S25: ids-scope agent proposes `object.create`, and a field op on a readable object outside its list, both refused; same op on a listed object accepted.

2. **MEDIUM. The slot bullet in "Your calls" misdescribes today's behavior and hides the cap being decided.** Today a field with no slot is not broken: values store and read fine, it just cannot sort, filter or serve the related endpoint. The refusal turns an 8-slot pool into a hard lifetime cap per object, since retire never frees a slot, and the pool is shared by text, select and lookup, not "8 text". After seeding, Person has 3 of those slots left, Opportunity 4, Task 5, Company 5. Shakur should decide on those numbers. Fix: reword the bullet to "a field that would get no index slot will be refused instead of created unindexed; this caps text, select and lookup fields at 8 per object for life, retired ones included, and standard objects already use 3 to 5", and correct "8 text" in Slots to "8 shared by text, select and lookup". Keep the refusal if he accepts the cap.

3. **LOW. "Standard field" has no definition and the owner summary is narrower than the rule.** Fields carry no standard marker, only objects do. Fix: define it as "a field on an `isStandard` object whose key appears in that object's entry in `convex/lib/standard.ts`", so custom fields humans add to Task stay retirable, and reword the "Your calls" bullet to say all seeded fields on built-in objects, not just the ones Today and the handoff use.

4. **LOW. One setup write is neither evented nor exempted.** `seed:releaseStandardSlots` patches `slot` off standard fields through `releaseSlot`. "Every setup write is evented" and S14 miss it. Fix: either it writes a setup event with actor operator and joins S14, or it is named as the second exemption next to org-creation seeding.

5. **LOW. The Operations table mixes propose-time and approval-time refusals.** "Existing key" for `object.create` can only be checked at approval, since the draft rightly says key uniqueness is not checked at propose, while "standard object keys" is a shape check. Fix: split the column into "refused at propose" and "refused at approval", or tag each entry.
