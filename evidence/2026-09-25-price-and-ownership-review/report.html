Source: docker --context colima-remold-proof exec remold-marketing-proof-web-a, read-only, app/release_metadata.json version 7.2.1. All paths below are under /var/www/html/docroot/app/bundles/.

Why A 175 became 176 then 177, and DNC disappeared

  1. The replay submits server-side without a tracking cookie. For a non-kiosk form, FormBundle/Model/SubmissionModel.php:941-947 uses contactTracker->getContact(). Because nothing is tracked, LeadBundle/Tracker/ContactTracker.php:266,269-290 persists a new anonymous contact (176).
  2. Mapped email matches the fixture: SubmissionModel.php:1021-1031. The anonymous contact has no unique fields, so there is no conflict and it has an id. :1042 is false, and :1056 calls merge($lead = anonymous, $foundLead = canonical). The new anonymous contact wins.
  3. LeadBundle/Deduplicate/ContactMerger.php:46-77 (sha256 1b26e282…) merges fields, owners, points, tags and companies, then :75 deletes the loser. No merge step or post-merge listener moves DNC. LeadBundle/EventListener/LeadSubscriber.php:273-312 moves event log, points log, lists, notes and devices. EmailBundle/EventListener/LeadSubscriber.php:43-49 moves stats only. LeadBundle/Entity/DoNotContact.php:78 is addLead(true,'CASCADE',…), so the suppression is deleted with the loser.
  4. ContactMerger.php:276-288 writes a merge record. That is why GET /contacts/175 returned the 176 data. replay.mjs contact() never checks returned.id === requested id, so before.json labels merged 176 data as contact 175.
  5. Unmapping firstname stops :1108 from writing the name. The merge still happens because it is driven by the email match plus the tracked anonymous contact, which explains 177 !== 175.

What kiosk mode changes

SubmissionModel.php:950-955 skips the tracked contact. :1042-1044 uses the found contact without merging. :1066 skips the new-contact-on-conflict path. :1098 skips the IP link. :1160-1166 sets a system contact with no cookies. With firstname unmapped, :1108 writes only the email, which is unchanged. For a single exact match, this removes the merge that deleted the DNC. Form.php:273-276,371 confirms inKioskMode is a persisted, API-serialized field. The historical form 1 is not touched.
