# Job A: M0 safe floor (code parts)
Branch: m0/safe-floor. Job id: A-m0.

Context: app.remoldcrm.com (Cloudflare Worker serving ./dist, see wrangler.jsonc) runs this code against Convex production deployment nautical-viper-899 (https://nautical-viper-899.convex.cloud). The developer's .env.local points at the OLD deployment gallant-pika-581 and still carries a Clerk key, so a routine `pnpm build && wrangler deploy` would ship a frontend aimed at the old database. Production sign-in today uses the WorkOS staging client; frontend env vars are read in src/main.tsx, src/lib/identity.tsx, src/components/AgentsCard.tsx (VITE_CONVEX_URL, VITE_WORKOS_CLIENT_ID, VITE_WORKOS_REDIRECT_URI, VITE_AUTH_SESSION_MODE, VITE_ROUTER).

Build:
1. One production deploy command, `pnpm deploy:prod` (ops/deploy/prod.mjs, plain node, no new deps). It must: refuse a dirty git tree; refuse if HEAD is not on a branch whose commit exists on origin (so what ships is recoverable); run typecheck, tests, test:authority and verify:release; build the frontend with production values taken from a committed, non-secret file (ops/deploy/prod.json: convex URL, WorkOS client id, redirect URI, session mode) and never from .env.local (prove .env.local cannot leak in, e.g. by building with an explicit env and checking the built bundle contains the prod convex URL and not gallant-pika-581); then run `convex deploy` against prod and `wrangler deploy`. Give it `--dry-run`, which does every check and the build and prints the exact deploy commands without running them. Fill prod.json with: convexUrl https://nautical-viper-899.convex.cloud; for the WorkOS values read what the current live bundle needs from src/lib/identity.tsx and leave clearly marked placeholders the coordinator will fill (the coordinator knows the staging client id); the build must refuse to run if a placeholder is left.
2. Rollback that keeps data: `pnpm deploy:prod --ref <git-sha>` deploys an older commit's code (frontend + Convex functions) onto the same production database, from a temporary git worktree, with the same checks. It must refuse a ref whose convex/schema.ts would reject current data shapes as far as can be checked locally: at minimum refuse a ref older than the rollback target pinned in ops/release/notes.json. Document in ops/deploy/README.md (short) how to roll back, and that the 2026-09-29 Cloudflare rollback to the old database loses any data written since.
3. Workspace creation limited to the owner and invitees: convex/orgs.ts `create` currently lets any signed-in user create a workspace. Allow it only when the signed-in user's verified email is in env REMOLD_WORKSPACE_CREATORS (comma-separated, case-insensitive) or env REMOLD_OPEN_SIGNUP === "1". Invited users keep joining through invites (convex/invites.ts) unaffected. The UI where a new user would create a workspace must show a plain message instead of failing silently. Tests: stranger refused, listed creator allowed, invitee still joins.
4. Backups: ops/backup/export.mjs runs `convex export --prod --path <dir>/nautical-viper-899-<UTC stamp>.zip` into a folder given by env REMOLD_BACKUP_DIR (default ~/Documents/CodeMyVibe/Backups/remold), appends a sha256 line to SHA256SUMS there, and deletes nothing. ops/backup/restore-drill.mjs <zip> restores a zip into a throwaway LOCAL Convex backend (reuse how ops/migrations/rehearse.mjs or ops/release/snapshot-drill.mjs starts one; never a hosted deployment), then re-exports and compares row counts table by table against the zip and exits non-zero on any mismatch or missing table. Prove the drill can fail: corrupt a copy of a zip (drop rows from one table) and show the drill reports it. Prove it passes on a zip exported from a seeded local backend.
5. The payment callback HTTP route(s) in convex/http.ts (Stripe/P4 integration callbacks) are unused in production. Make them answer 404 unless env REMOLD_PAYMENT_CALLBACKS === "1", with a test both ways. Keep the code.

Done when: all five have fail-before/pass-after evidence, full suites pass, `pnpm deploy:prod --dry-run` output is in the handover (it will stop at the placeholder check unless you fill test values in a temporary copy; show both the refusal and a dry run with temporary values), and the handover lists exact commands the coordinator runs on the Mac (which holds prod access) to do a real deploy and a real restore drill.
