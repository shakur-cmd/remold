# Job G: M2 your active clients in Remold (import tool + demo cleanup)
Branch: m2/import. Job id: G-m2.

Context: Shakur's live workspace holds only the demo rows from convex/seed.ts (companies, people, deals, a project, tasks, notes). His real clients are drafted in a private JSON file (not in this repo) with this shape:
{"records":[{"tmpId":"c1","object":"company","values":{"name":"...","domain":"..."},"sources":["..."]},
 {"tmpId":"p1","object":"person","values":{"name":"...","email":"...","company":"@c1"}},
 {"tmpId":"t1","object":"task","values":{"title":"...","done":false,"about":"@o2","dueDate":"2026-11-30"}}, ...]}
Objects used: company, person, opportunity, project, task, note. "@tmpId" values are references to earlier records. Value keys are field keys from convex/lib/standard.ts (check them; the drafter may have used a key that differs, e.g. dueDate vs due: map known aliases and refuse unknown keys with a clear error listing them).

Build:
1. An internal mutation (not callable by clients) that imports such a batch into one workspace given by orgId, as one transaction: resolves @tmpId references, writes every record through the same applyChange path with events attributed to a clearly named importer actor (so history shows "import 2026-10-02"), and stores a batch key so running the same batch again creates nothing and reports "already imported". Values are validated by the normal field validation (resolveValues); any invalid record fails the whole batch with the tmpId and reason. Refuse any value matching credential patterns (password, passwd, secret, token, api key, sk_/pk_/re_ prefixes, long base64-like runs) as a defensive check.
2. A node script ops/import/records.mjs <file.json> --org <orgId> [--prod] [--dry-run] that validates the file locally (references resolve, objects known, keys known, credential scan) and then calls the internal mutation through `convex run` (with --prod only if passed). --dry-run calls a query variant that validates against the live schema without writing and prints counts per object.
3. Demo cleanup (REVISED by the coordinator on 2026-10-02 after round 1; this replaces the provenance requirement in the original wording): the boundary is an explicit, reviewed id list. The dry run prints a plan; a person (the coordinator) reviews it; the real run deletes exactly the listed ids and refuses the whole run if any listed record has any event besides its create, or is referenced by a record outside the list, or is not a seed title/object. It must never update or delete anything outside the list. Proving seed origin is NOT required. Original wording kept for history: an internal mutation that deletes exactly the records convex/seed.ts creates in a workspace (match by the seed's titles AND object AND that they were created by the seed, e.g. no events from a human after creation, so a demo row a human edited is kept and reported), records a delete event for each, and supports a dry run listing what would go. Never touches non-seed records. Script: ops/import/remove-demo.mjs --org <orgId> [--prod] [--dry-run].

Done when: tests prove a batch imports with links intact; running it twice creates nothing the second time; an invalid reference or unknown key fails the whole batch with nothing written; a credential-looking value is refused; demo cleanup removes only seed rows and keeps an edited one; dry runs write nothing. Full suites pass. Handover lists the exact commands for the coordinator to run against production (dry run first).
